# Overview

File Analyzer is an offline file analysis project for **Windows and macOS**. It provides local file import, metadata tables, basic comparisons, static spectrograms, privacy metadata inspection, and PDF document/page analysis. A TypeScript API and metadata command-line interface are also available. All file processing stays on your computer.

The application is developed and tested on Linux. Native Windows/macOS packaging and validation are configured separately; see [packaging instructions](docs/PACKAGING.md) for build prerequisites and release checks. No release has been published yet.

# File Analyzer

一个面向 **Windows 和 macOS** 的离线桌面小工具：**拖入文件 → 查看参数 → 按需查看频谱**。

当前提供 Electron 窗口、文件拖放/选择、详情与可排序的多文件对比、参数解释与用途计算、隐私元数据检查、PDF 专项分析、按音轨生成静态频谱，以及 TypeScript 接口、元数据命令行和自动化测试。第三阶段同时补充完整包构建和原生平台 CI；当前云环境为 Linux，Windows/macOS 的实际构建与安装验收结果须以原生平台运行记录为准，尚未发布 Releases 应用包。

本次源码拓展包含文档 512 MiB／音视频 2 GiB 上限、六语言界面、黑底带色标的频谱图，以及语言切换时保留频谱横向位置的修复。操作方式、范围备注、审阅修复与验证结果见 [更新记录](CHANGELOG.md)。

Windows x64 完整离线版使用 `npm run package:offline` 统一构建，随包包含 FFprobe、FFmpeg、ExifTool 及运行文件；用户无需另装组件。构建成功后输出安装器、中文使用说明、SHA-256 校验值及实际体积报告。原生构建与安装验收方式见 [打包说明](docs/PACKAGING.md)。

支持简体中文、English、日本語、한국어、Français、Español 六种界面语言，可在窗口右上角切换。

## 项目目标

收到或下载文件后，用户可以快速了解文件的实际规格，辅助判断它是否适合剪辑、打印等用途，减少在不同工具之间切换。

- 支持 Windows 和 macOS。
- 核心功能在本机离线完成，不上传文件，不依赖云端服务。
- 用一个窗口完成操作，支持单文件详情和多文件基础对比。
- 尽量提取文件中实际存在的参数，按类别组织，并说明数据来源和限制。
- 为选中的音频或视频音轨生成一张静态频谱图。
- 接受任意类型的文件；对首批支持格式提供专属解析，其他格式提供基础信息。

控制项目规模：优先复用成熟工具，不自行开发媒体解码器或通用解析框架。新功能只有在实际使用中发现需要时才评估，不将扩展方向自动加入开发计划。

## 运行桌面应用

源码运行需准备下文的 Node.js、FFprobe 和 ExifTool；生成频谱还需要 FFmpeg。在仓库根目录运行：
### node 版本需至少22.12.0
```sh
winget install --id OpenJS.NodeJS.LTS --exact --source winget （在终端使用此指令，下载最新LTS版本）
```
```sh
npm -v
nvm list
nvm use <指定版本号>

npm ci
npm start
```

`npm start` 会构建并启动 Electron。已经构建过时可使用 `npm run desktop`。首次安装会下载开发所需的 Electron；应用运行及解析文件无需联网。

- 点击“添加文件”或拖入一个、多个本地文件；也可使用 `Ctrl+O` / `Cmd+O`。
- 左侧选择文件，右侧查看基础信息、专属参数和各媒体轨道。
- 列表包含至少两个文件时，可切换“参数对比”，比较当前列表中的常用参数。混合类型使用“不适用”，缺失属性显示“未记录”。
- 每个文件分别显示等待、解析中、完成、部分解析或失败。部分解析及失败可点击“重新解析”。
- 音视频详情中选择音轨，点击“生成频谱”。生成时可取消，也可继续导入或检查其他文件；一次生成一张图，失败可重试。
- “移除”和“清空列表”只移除本次会话中的条目，不删除或修改原文件。关闭窗口后不保存导入路径和结果。

元数据在后台 Worker 中串行解析，频谱使用独立后台任务，单个文件失败不影响其他文件。工具优先使用应用随包资源，其次使用启动前配置的 `FILE_ANALYZER_FFPROBE`、`FILE_ANALYZER_EXIFTOOL`、`FILE_ANALYZER_FFMPEG`，最后查找系统 `PATH`。修改环境配置后重新启动应用；缺少 FFmpeg 只影响频谱。取消生成、移除对应文件或退出应用时会回收正在运行的工具。没有单独的工具设置页面，也不在应用运行时联网下载工具。

```sh

```

## 文件大小与资源上限

单个 PDF、DOCX、XLSX、PPTX 文档最多 **512 MiB（536,870,912 字节）**，受支持的音频、视频文件最多 **2 GiB（2,147,483,648 字节）**，按 1024 进制计算，等于上限时允许解析。桌面、CLI 和 API 共用同一规则，按内容识别后的类别检查；超限返回 `FILE_SIZE_LIMIT`，保留基础文件信息，专属参数和隐私检查不执行，其他文件继续处理。直接调用频谱 API 也检查源文件的 2 GiB 上限。

源文件大小与解析资源限制分别计算：Office 所需 XML 仍限制单部件 4 MiB、合计 12 MiB；频谱仍限制解码数据 256 MiB，因此较长音轨即使源文件小于 2 GiB，也可能无法生成完整频谱。PDF 结构线程的旧生代堆预算为 512 MiB，不含文件缓冲等内存，默认结构检查超时为 60 秒；其他内容识别和元数据工具默认 15 秒。显式传入 `timeoutMs` 或 CLI `--timeout` 时，该值也约束 PDF 结构检查。

## 运行解析核心

准备 Node.js **22 或以上**（推荐 24，见 `.node-version`）、FFprobe 和 ExifTool。完整测试还需要 FFmpeg。工具可安装到系统 `PATH`，也可通过下述选项指定路径。ExifTool 的 Office 元数据读取需要相应 Perl 依赖（如 `Archive::Zip`）；缺少时会提示问题，并保留直接读取到的 Office 属性和结构数量。

在仓库根目录运行：

```sh
npm ci
npm run build
npm run analyze -- "path/to/file.mp4"
npm run analyze -- "path/to/photo.jpg" "path/to/document.docx"
```

默认输出参数表格。需要纯 JSON 时直接调用构建后的命令，避免 npm 的运行提示混入输出：

```sh
node dist/src/cli.js --json "path/to/file.flac"
node dist/src/cli.js --ffprobe "/path/to/ffprobe" --exiftool "/path/to/exiftool" "path/to/file.mp4"
node dist/src/cli.js --help
```

选项还包括 `--tools-dir <目录>` 和 `--timeout <毫秒>`（默认 15000，允许 1 到 2147483647 的整数）。可使用环境变量 `FILE_ANALYZER_FFPROBE`、`FILE_ANALYZER_EXIFTOOL` 指定工具。路径含空格时需要引号；以 `-` 开头的文件名放在 `--` 后。

退出码：`0` 表示成功（含未知格式的基础信息）；`1` 表示至少一个文件失败或部分解析；`2` 表示命令参数错误。批量解析中单个文件失败不影响后续文件。

### 程序接口

```js
import { analyzeFile, analyzeFiles } from './dist/src/index.js';

const result = await analyzeFile('/path/to/file.mp4');
const results = await analyzeFiles(['/path/to/photo.png', '/path/to/book.xlsx']);
```

生成单个音频轨道的频谱（`streamIndex` 是 `result.streams` 中实际的音频轨道 `index`，并非“第几个音轨”）：

```js
import { generateSpectrogram } from './dist/src/index.js';

const stream = result.streams.find(stream => stream.type === 'audio');
if (stream) {
  const spectrum = await generateSpectrogram(result.path, stream.index, {
    ffmpegPath: '/path/to/ffmpeg', // 也可省略并使用环境变量或 PATH
  });
  // spectrum.imageDataUrl 是 PNG；同时返回采样率、时长、尺寸和声道数。
}
```

接口返回文件类别、识别方式、整体状态、`fields`、分轨道的 `streams`、`issues` 和解析工具的 `rawMetadata`。每个字段包含稳定的 `key`、中文名称、值、状态、来源和可选单位/说明；缺失值使用 `null`。字段状态为 `present`、`missing`、`not_applicable`、`unknown` 或 `error`；整体状态为 `ok`、`partial` 或 `error`。

可选的第二个参数使用 `timeoutMs` 配置超时，与 CLI 共用整数和范围校验。无效配置会在分析文件之前抛出 `InvalidOptionsError`（`code: 'INVALID_OPTIONS'`），不会误报为文件损坏或识别失败。

文件按内容识别，扩展名仅作回退提示。Office 工作表和幻灯片数量直接读取 OOXML 结构；Word 页数和字数保留保存属性的来源说明。FFprobe 仅允许本地文件/管道协议，不根据媒体内容访问网络地址。

FFprobe 即使退出码为 `0`，也可能报告媒体数据损坏。此类诊断会保存在 `issues` 中并将结果标为 `partial`，同时保留已提取的参数；元数据解析不等同于完整解码或完整性检测。

## 初版支持范围

下表格式已完成阶段一解析验证。实际字段取决于文件内容、编码方式和解析工具；并非每个文件都包含全部信息。

| 类别 | 首批格式 | 可提取的主要参数 |
| --- | --- | --- |
| 音频 | MP3、FLAC、WAV、AAC、M4A、OGG | 编码格式、时长、码率、采样率、声道数与布局、位深、编码是否无损，以及可用标签 |
| 视频 | MP4、MKV、MOV、WebM | 容器格式、视频编码、像素尺寸、帧率、时长、码率，以及各音轨、字幕轨的可用参数 |
| 图片 | JPEG、PNG、WebP、TIFF、GIF | 像素尺寸、DPI、位深、色彩空间、透明度，以及可用的 EXIF 等元数据 |
| Office | DOCX、XLSX、PPTX | 作者、文档创建与修改时间、工作表数量、幻灯片数量，以及文档中可读取的统计信息 |
| PDF | PDF | 页数、逐页 MediaBox 尺寸、旋转、加密状态、版本及可读取的文档属性 |
| 其他文件 | 不限扩展名 | 文件名、大小、文件系统时间，以及能够识别的实际文件类型 |

格式名称与编码名称分别展示。例如，MP4 是容器格式，其中的视频和音轨可以使用不同编码；M4A 和 OGG 的编码属性也需要根据实际音轨判断。

多页 TIFF 的标准图片参数取第一页；其他页面保留在 API 的原始元数据中，不参与第一页的 DPI 冲突判断。

Office 仅提取现成的文档属性和结构信息，不启动办公软件进行排版计算。上述格式是首批支持清单，不承诺读取每一种文件变体的全部参数。

## 初版边界

当前提供文件导入、参数表格、基础对比、静态频谱，以及下述参数解释、用途计算、隐私元数据检查和 PDF 分析，不包含：

- 复杂对比工作台、自动质量评分或“真无损／假无损”鉴定。
- 频谱缩放、时间范围交互、编辑功能或自研频谱引擎。
- 持久化分析缓存、任务队列管理界面或历史记录系统。
- 文件编辑、转码、自动判断打印或剪辑适用性。
- 插件系统、云端服务或旧版 DOC、XLS、PPT 的专属解析。
- 独立的精简可执行安装包、依赖工具自动下载或自动更新系统。

这些功能没有默认实施计划，后续按真实需求单独决定。

## 参数解释与用途计算

详情与对比表中的常用字段提供可展开的“参数解释”，覆盖编码、码率、采样率、位深、声道、像素、DPI、帧率和 Office 统计等概念。点击或用键盘展开即可查看；原始值、来源和异常状态保持独立。

- **图片打印尺寸**：详情中的“用途计算”根据像素宽高和目标 DPI 换算厘米尺寸：`像素 ÷ 目标 DPI × 2.54`。默认 300 DPI 是明确的计算条件，不是文件元数据的默认值。可输入 1～9600 的小数，点击“计算尺寸”或按 Enter。修改条件后旧结果立即失效；无效输入或缺失像素尺寸会显示原因。结果假设不裁切、不重采样，不保证实际印刷质量，也不修改文件。
- **音轨 PCM 数据量**：按每个音轨的 `采样率 × 位深 × 声道数 × 秒数 ÷ 8`，估算未压缩、紧密存储的 PCM 每分钟数据量。有该轨道的有效时长时，也展示总量；不使用容器时长替代。缺失或不适用的位深等参数不会被猜测为 16 bit。估算不含文件头、对齐和元数据，不代表当前压缩文件大小或实际音质。

打印计算条件在本次会话切换文件或详情/对比时保留，移除或重新解析文件时清除。此功能完全离线；自动判断“真无损”、印刷质量或剪辑软件兼容性仍不在范围内。

## 隐私元数据检查

解析后，详情中的“隐私元数据检查”集中列出已读取的 GPS/位置、作者/署名/联系信息、设备品牌型号和序列号等记录，包括 MOV 文件的 `com.apple.quicktime.author`、`com.apple.quicktime.make` 和 `com.apple.quicktime.model` 标签。发现项默认折叠，展开后显示值及来源。检查仅在本机读取，不修改或清理元数据、不上传文件、不保存检查历史。

状态区分“已检查支持的字段”“检查不完整”“未能检查”和“未支持此格式”。工具缺失、损坏和加密等问题不会显示为完整检查。未发现支持字段不代表文件不含隐私：正文、图像内容、批注、附件、历史版本和未支持的厂商字段不在范围内。音视频检查 FFprobe 返回的文件/轨道标签；图片、Office、PDF 复用 ExifTool，Office/PDF 还检查直接读取的文档属性。系统路径、文件名及系统时间不作为内部隐私发现项。最多展示 100 项、每项最多 2048 字符；超出范围会标为检查不完整。

CLI 表格展示检查摘要、发现项和来源。API/JSON 的 `privacy` 包含 `status`（`checked`、`partial`、`unavailable`、`unsupported`）、`findings`、`checkedSources`、`limitations`，可供后续批量筛选使用。发现项不是安全评分，`checked` 也不代表没有隐私。

## PDF 专项分析

PDF 按内容识别，详情/对比显示页数、加密状态和版本，文档属性包括可读取的作者、标题、主题、关键词、创建应用、生成程序及记录时间；缺失属性保持“未记录”，不自动填入解析器信息。作者同时进入隐私检查。

“PDF 页面尺寸”可展开逐页查看 MediaBox 宽高（pt 和换算的 mm）及旋转角度。尺寸计入页面 UserUnit，但未应用旋转，也不等同于 CropBox 裁切区或打印机可打印区域。混合尺寸文档分别展示各页。单页属性异常时标明对应页码，保留总页数、文档属性和其他可读取页面，并标为部分解析。API/JSON 的 `pdfPages` 保留实际检查的页码和尺寸。

固定版本 pdf-lib 在独立线程中只读解析页面结构，ExifTool 读取文档元数据。检查不渲染页面、不执行 PDF JavaScript、不访问外部链接、不修改文件，也不尝试解密。加密 PDF 只保留无需解密即可读取的记录，并标为部分解析。源文件上限为 512 MiB，结构线程旧生代堆预算为 512 MiB（不含文件缓冲等内存），默认结构检查超时为 60 秒，逐页尺寸只检查前 200 页。超过源文件上限时只展示基础信息；结构超时、内存预算不足或部分页面未检查时，保留已经读取的可用元数据并说明未检查范围。`--timeout` 同样约束结构解析；移除文件和退出应用会终止解析线程。此功能不构成恶意内容检测、完整性保证或密码破解，不含预览、OCR、字体嵌入审计、编辑或隐私清理。

## 使用流程与界面

1. 拖放文件到应用，或通过文件选择器导入一个、多个文件。
2. 应用调用现成工具解析文件，以表格显示基础信息和技术参数。
3. 点击文件切换详情；需要比较时，查看多个文件的基础参数对比表。
4. 对当前音视频文件选择音轨，点击生成并查看静态频谱图。

界面由三个主要区域组成：

| 区域 | 职责 |
| --- | --- |
| 文件列表 | 展示导入文件、当前选择及解析状态 |
| 参数表格 | 展示单文件详情或多文件对比，包含字段名、值、单位和必要的来源说明 |
| 频谱区域 | 选择音轨、点击生成、显示生成中或失败状态，以及静态频谱图 |

多文件对比先显示文件名、类型、大小等共同字段，同类型文件增加码率、时长或像素尺寸等常用字段。不提供自定义对比规则，其他参数在单文件详情中查看。

对比表中的文件列可独立排序：拖动列标题中的“拖动排序”到目标列左侧或右侧，整列参数随之移动；蓝色插入线提示放置位置。拖到表格左右边缘时自动横向滚动。也可使用每列的左右箭头，或聚焦“拖动排序”后按 `Alt+←` / `Alt+→`。“恢复添加顺序”可重置排序。列顺序在本次会话切换视图、解析完成和重试时保留；新文件追加到末尾，移除文件只删除对应列。左侧文件列表及实际解析队列仍按添加顺序排列。拖动取消不改变顺序。

## 数据准确性与展示规则

- **区分字段状态**：有效值、文件未记录、不适用、无法可靠判断、解析失败。不能把缺失值默认为 `0`，也不能将解析失败显示为正常的空白结果。
- **保留单位与来源**：统一展示码率、时长和尺寸等单位，区分文件记录值、解析工具报告值及计算值。
- **区分不同层级**：文件总码率与单音轨码率分别展示；多音轨、多视频轨分别列出。
- **区分时间来源**：文件系统时间和 Office 文档内部时间分别展示，不混为同一属性。
- **区分像素与 DPI**：图片可能没有 DPI，或包含冲突的分辨率元数据；不以默认值代替缺失信息，不把 DPI 当作像素尺寸。
- **说明 Office 统计限制**：Word 页数、字数如果来自文档保存的统计信息，应标明来源。这些值可能过时，初版不保证与 Word 实际重新排版后的结果一致。
- **按内容识别类型**：尽可能结合文件内容和解析结果判断，不仅依赖扩展名；无法识别时仍提供基础信息。

## 频谱可视化

频谱用于辅助观察音频的频率分布、压缩痕迹，以及疑似从有损音源转为无损编码的情况。视频文件的频谱针对其中的音轨生成。

按需生成一张 1200 × 744 的静态时频图，采用黑底、白色坐标和蓝紫—红—黄—白的热力配色，顶部显示文件名与音轨参数。横轴为完整音轨的相对时间（分:秒，短音轨保留小数秒），纵轴为线性频率（kHz，从 0 到原采样率的一半），均带中间刻度；右侧色标对应 −120～0 dBFS 的对数幅度范围。窄窗口可在图表内横向滚动查看完整坐标及色标。多声道合并展示，图和说明均对应当前选择的实际音轨。初版不提供交互式缩放、导出或时间片段选择。

### 分析边界

“编码是否无损”和“音源是否真正无损”是不同问题。FLAC 等文件采用无损编码，并不能证明它此前没有经历有损压缩。

高频截止等现象可以提供线索，也可能来自录音设备、滤波或音源本身。初版展示客观参数与可视化依据，不输出“真无损／假无损”的自动鉴定结论。

### 性能要求

- 通过后台调用解析工具保持界面响应，频谱按需生成并显示处理状态。
- 不在界面进程中加载全部解码音频；长文件允许耗时较久，失败时明确说明原因。
- 高频分析保留足够的采样率，避免降采样破坏观察依据。
- FFmpeg 的 `showspectrumpic` 会缓存浮点音频；存在音轨时长时，生成前按 `采样率 × 声道数 × 时长 × 4` 检查。解码链另有实际样本数硬限制，超过 256 MiB 时明确拒绝并建议先截取较短片段，不自动降采样或仅截取开头冒充全长。此限制针对音频缓存，并非整个应用的内存上限；44.1 kHz 双声道约可覆盖 12 分钟，高采样率、多声道的可用时长更短。
- 横轴时长来自实际解码样本数，避免把容器时长或音轨起始偏移当成实际音频时长。无法可靠确定采样率、声道或实际有效样本数时不生成图。频谱工具调用默认最多 120 秒，超时会终止工具，参数结果仍保留。
- 音轨中途改变采样率、声道布局或采样格式时，会明确提示暂不支持生成完整频谱，不将最后一段冒充整条音轨；文件参数仍可查看。

## 技术选型

初版采用 Electron + TypeScript，优先降低开发和维护难度。应用代码主要使用 TypeScript；具体版本以 `package.json` 和锁文件为准。

| 组件 | 建议方案 | 职责 |
| --- | --- | --- |
| 桌面应用 | Electron + TypeScript | 单窗口界面、文件导入、表格和图片展示 |
| 界面 | HTML/CSS + TypeScript | 简单表格与图片展示，初版无需引入 React |
| 音视频元数据 | FFprobe | 读取容器、编码及各媒体轨参数 |
| 静态频谱 | FFmpeg | 使用现有音频解码和频谱生成功能输出图片 |
| 图片与通用元数据 | ExifTool | 读取图片属性、EXIF 及其他支持的元数据 |
| Office 解析 | 优先复用 ExifTool，必要时补充少量 OOXML ZIP/XML 解析 | 先验证现成工具能读取的属性，仅为缺少的必要字段增加解析代码 |

代码保持简单：界面负责展示，少量解析函数负责调用工具、整理字段和处理错误，不要求预先建设多层架构、任务框架或插件接口。

需要为 Windows 和 macOS 准备对应的解析工具，并在两个系统上实际验证。Electron 和解析工具会增加安装包体积，首版接受这一代价，不同时开展安装包极限压缩工作。

## GitHub 托管与交付

项目计划通过 GitHub 公开托管源码，通过 GitHub Releases 提供完整应用包，初版不以应用商店或软件中心上架为目标。两种使用方式复用同一套代码：

| 方式 | 内容 | 使用前提 |
| --- | --- | --- |
| 完整版 | 应用、Electron、FFmpeg/FFprobe、ExifTool 及所需运行依赖 | 下载对应平台的包后即可使用，无需另外安装解析工具 |
| 源码版 | 仓库中的应用代码、依赖清单及运行说明 | 用户自行安装 Node.js、项目依赖和需要的解析工具后运行 |

源码版通过仓库或 GitHub 源码归档提供，不另外维护一套精简可执行安装包。源码本身较小，但运行时仍需要安装依赖；完整应用包的大小以实际构建结果为准。

### 外部工具查找

每个工具分别按以下顺序查找：

1. 应用随包提供的工具。
2. 用户明确配置的工具路径。
3. 系统 `PATH` 中的工具。

缺少或无法运行某个工具时，提示受影响的功能，不阻止基础文件信息和其他可用功能。应用不自动联网下载工具，核心文件分析仍在本机完成。

### 打包要求

- 外部工具及附属文件放入真实资源目录，供应用调用。
- Windows 的 ExifTool 一并携带其附属文件目录；macOS 的 ExifTool 需要处理 Perl 运行时和库依赖。
- 完整版在没有预装解析工具的目标电脑上验证，确保运行依赖齐全。
- 发布时记录附带工具的版本并遵守对应的再分发许可；项目自身的开源许可证待确定。

构建命令、工具资源布局、固定来源与校验、许可记录和原生平台验收见 [打包说明](docs/PACKAGING.md)。构建阶段可以联网获取固定依赖，安装后的分析流程离线运行。尚未发布 Releases 应用包。

## 开发顺序与验收

### 阶段一：解析基础（已实现）

- 实现首批格式的识别和参数提取。
- 整理必要的字段名称、单位和错误信息。
- 对未支持格式提供基础信息。

验收：使用各类代表性文件，核对实际提取的字段、单位和来源；文件缺少元数据、损坏或类型不匹配时，能够给出明确结果。

### 阶段二：桌面交互（已实现）

- 实现拖放、单文件详情和多文件对比。
- 展示处理中、成功与失败状态。
- 将耗时任务放在后台，保持界面响应。

验收：单文件和批量导入均可完成；一个文件解析失败不阻止其他文件显示结果；混合类型对比不将不适用字段误报为缺失。

### 阶段三：频谱与跨平台打包（功能与构建流程已实现，原生验收待执行）

- 调用 FFmpeg 为音频和选中的视频音轨生成静态频谱图。
- 显示处理状态和生成的图片，不实现交互式频谱编辑。
- 提供 Windows 和 macOS 完整包构建脚本、随包工具准备与原生 CI 验证流程。
- 在对应系统实际运行构建、安装与离线验收后，才能宣布该平台安装包可交付；Linux 云环境的通过结果不能替代这一步。

验收：使用已知频率的音频核对频谱显示，并检查多音轨选择与长文件的响应情况；断网时核心流程可用；两个系统均能安装、解析文件并生成频谱。

### 阶段四：分析辅助与对比增强（已实现）

- 提供参数解释、图片打印尺寸计算和按音轨的 PCM 数据量估算。
- 提供带来源及检查状态的隐私元数据检查，以及 PDF 文档属性和逐页尺寸分析。
- 支持对比文件列独立拖动排序、边缘自动滚动、键盘移动和恢复添加顺序。
- 提供中、英、日、韩、法、西六种界面语言，本机保存语言偏好，支持 CLI `--lang`。

验收：Linux 环境通过 191 项核心测试和 36 项真实 Electron 端到端测试，包含异常 PDF 保留可用结果、QuickTime 隐私标签、恢复排序后的焦点可见性、512 MiB PDF 与 2 GiB WAV 临界大小、多语言切换及偏好恢复，以及频谱刻度、真实色标和窄窗口滚动。另通过 8 项打包规则测试。具体范围与限制见 [更新记录](CHANGELOG.md)。
